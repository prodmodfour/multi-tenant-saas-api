## 013 — Add idempotency support

Status: TODO

Implement idempotency middleware/service or explicit route integration.

Support `Idempotency-Key` header for at least:

- `POST /orgs`
- `POST /orgs/{org_id}/projects`
- `POST /orgs/{org_id}/api-keys`

Rules:

- Same principal + method + path + key + body hash returns stored response.
- Same key with different body hash returns conflict.
- Records should be scoped to principal and organisation where appropriate.
- Do not store secrets in response snapshots if avoidable; be especially careful with API key creation.

For API key creation, either avoid idempotent replay of raw key material or clearly document a safer behaviour. Prefer not returning raw key again on replay unless the design can do so safely.

Add tests for:

- idempotent replay
- conflict on changed body
- tenant scoping
- no secret leakage
